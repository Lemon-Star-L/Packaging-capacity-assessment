## 1. 项目概述

项目将“备件收货业务”按日期与模块汇总，建立“每日各模块作业数量——当日人员总工时”矩阵，并基于预设方法估计模块单位工时。“主数据清洗”、“模块补充匹配”属于前置辅助环节；“矩阵合并”与“参数求解”属于核心计算环节。

模型采用以下基本关系：

$$
T_i = \sum_{j=1}^{m} Q_{ij}t_j + \varepsilon_i
$$

其中，`T_i` 为第 `i` 个样本日的总工时（小时），`Q_ij` 为第 `i` 个样本日内模块 `j` 的作业件数，`t_j` 为模块单位工时（小时/件），`ε_i` 为未被线性模型解释的差异。严格方程模式要求拟合等式成立；其他求解模式使用各自的损失函数或预测方法。

注：该关系属于模型假设，不表示已对单件作业时间进行现场测定。

### 1.1 脚本分工

| 脚本 | 作用 | 主要输入 | 主要输出 |
|:---|:---|:---|:---|
| `clean.py` | 清理件号主数据中的空值及重复件号 | `clean/模块信息.xlsx` | `clean/模块信息_清洗.xlsx` |
| `model.py` | 对指定的未分类备件进行辅助模块匹配 | `model/备件模块信息.xlsx`、字典 | `model/映射表（近似）.xlsx` |
| `pre_execute.py` | 逐期间生成每日模块数量与总工时矩阵 | 业务表、人员表、`data/Resource.xlsx` | `output/<期间>_result.xlsx` 及异常报告 |
| `merge.py` | 合并期间矩阵并剔除符合规则的重复方程 | `output/<期间>_result.xlsx` | `output/A_result.xlsx` 及删除、错误报告 |
| `execute.py` | 读取合并矩阵，求解或预测并进行结果诊断 | `output/A_result.xlsx`、`data/Resource.xlsx` | `output/execute_result.xlsx`、`output/execute_explain.xlsx` |

五个脚本**不会相互自动调用**；常规计算流程为 `pre_execute.py → merge.py → execute.py`；如基础映射需要维护，可先按需运行 `clean.py` 和 `model.py`，人工复核后再更新 `Resource.xlsx`。

## 3. 主数据预处理（按需）

### 3.1 `clean.py`：件号清洗

**输入：** `clean/模块信息.xlsx` 第一个工作表，必需列为 `件号`。  
**输出：** `clean/模块信息_清洗.xlsx`。

处理规则：按字符串读取源表；清理列名及件号前后空白；删除空件号行；对重复件号保留首次出现的完整记录。脚本不合并其他字段、不累计数量，也不比较重复行的完整性。控制台输出清洗前后行数。

该处理仅适用于“一件号一条主数据”的资料，不适用于需要保留同件号多笔交易的业务流水。源 Excel 如已将件号按数值存储并丢失前导零，脚本无法恢复。原文件不覆盖，同名结果文件会覆盖。

### 3.2 `model.py`：模块辅助匹配

**输入：** `model/备件模块信息.xlsx`，须包含 `映射表`、`模块信息_Operate` 两张工作表；另外需要 `model/direct/日用品字典.csv`、`model/direct/汽车配件字典.csv`。  
**输出：** `model/映射表（近似）.xlsx`。

| 数据位置 | 必需字段及约束 |
|:---|:---|
| `模块信息_Operate` | `备件名称`、`区`、`备件模块`，以及 `件号` / `备件编码` / `零件号` 至少一个；`备件SKU` 可选 |
| `映射表` | `备件名称`，以及 `模块名称` 或 `备件模块` |
| `日用品字典.csv` | `关键词`；`匹配方式`、`排除词`等字段按实际规则使用 |
| `汽车配件字典.csv` | `关键词`、`模块`；其他字段可用于判定说明 |
| `人工修正.csv` | `件号`、`备件名称`、`确认模块`；缺失时创建带表头的空模板 |

**当前配置：** `REPROCESS_UNCLASSIFIED = False`，仅处理源表中模块为 `#N/A` 的记录。设置为 `True` 后，还会处理空白及“未分类…”记录。当前 `MIN_SCORE = 82`、`MIN_MARGIN = 8`、`SHORTLIST = 100`，分别对应近似匹配分数阈值、候选分差阈值和初筛候选名称数量。

匹配优先考虑人工修正，然后结合日用品关键词、既有模块映射、名称规范化与主体相似度、汽车配件字典等规则判定。对未能确认的记录输出 `未分类` 或带参考类别的 `未分类（…）`，并提供判定依据与候选项。

输出包含三个工作表：

| 工作表 | 内容 |
|:---|:---|
| `近似` | 件号、货品名称、区、备件模块；保留本次待处理记录顺序与重复行 |
| `匹配明细` | 原始行号、SKU、件号、原分类、最终模块、匹配来源、复核标记、判定依据和最多三个候选 |
| `处理统计` | 程序版本、字典数量、匹配来源计数及排除无效映射数 |

匹配分数不是准确率；辅助归类及“未分类（…）”不应直接等同于经过业务确认的正式模块。该脚本不修改源文件，也不自动写入 `data/Resource.xlsx`。CSV 读取尝试 UTF-8（带 BOM）及 GB18030 编码。

## 4. 矩阵生成：`pre_execute.py`

### 4.1 当前主要参数

| 参数 | 当前值 | 含义 |
|:---|:---|:---|
| `PROCESS_MODE` | `2` | `1` 月度；`2` 年度文件，均按自然日归集 |
| `FIELD_MODE` | `1` | `1` 中文业务字段；`2` 英文业务字段，与期间模式独立 |
| `HOURS_PER_PERSON` | `11` | 人均日工时系数，单位小时/人 |
| `DATA_SUBDIR` | `execute` | 业务与人员文件所在子目录 `data/execute/` |
| `DATA_FILES` | `[]` | 留空自动扫描当前模式的业务文件；非空时指定文件 |
| `DATA_SHEET`、`PERSONNEL_SHEET` | `0` | 分别读取业务、人员文件的第一张工作表 |
| `PARTS_SHEET`、`MODULES_SHEET` | `备件信息`、`模块信息` | `Resource.xlsx` 内的工作表名称 |

### 4.2 文件命名与字段

| 数据 | 文件示例 | 必需字段 |
|:---|:---|:---|
| 月度业务及人员 | `2026_9.xlsx`、`2026_9_P.xlsx` | 业务字段见下；人员为 `日期`、`人数` |
| 年度业务及人员 | `2026_year.xlsx`、`2026_year_P.xlsx` | 同上 |
| 备件映射 | `data/Resource.xlsx` → `备件信息` | `件号`、`备件模块` |
| 模块对应 | `data/Resource.xlsx` → `模块信息` | `备件模块`、`自变量` |

业务字段随 `FIELD_MODE` 变化：

| 字段用途 | 中文模式 `1` | 英文模式 `2` |
|:---|:---|:---|
| 件号 | `件号` | `SUSR1` |
| 数量 | `预期收货数量` | `QTYRECEIVED_1` |
| 日期 | `收货日期时间` | `DATERECEIVED` |

表头按名称定位，不依赖列顺序。数量接受有效非负数值，以及如 `5,640`、`5，640` 的千位分隔文本；错误格式不被静默转换。`Resource.xlsx` 中模块自变量必须按照表内顺序连续编号 `x1`、`x2`……。

### 4.3 计算规则

每个样本日形成一行，前 `m` 列是模块件数，最后一列为总工时（小时），即：

```text
x1件数 | x2件数 | ... | xm件数 | 总工时（小时）
```

总工时按“当日人数 × `HOURS_PER_PERSON`”计算；同一天、同模块的有效交易数量求和，不要求源流水按时间排序，也不对同件号交易去重。矩阵按人员表日期升序排列，不主动补齐缺失的自然日。输出数值表**无表头、无日期列**。

关键异常处理口径：

| 场景 | 处理 |
|:---|:---|
| 人员日无业务，或当天模块数量全为零 | 数量与工时整行置零 |
| 有业务但人员数为零或缺失 | 对应日期矩阵置零，业务记录进入错误明细 |
| 业务日期不在人员日期表 | 不增加矩阵日期，相关业务进入错误明细 |
| 件号或模块映射失败 | 相关记录进入错误明细，其余有效记录可继续归集 |
| 部分业务映射失败且当天仍有有效业务 | 保留成功映射件数和完整日总工时，不按成功数量占比分配工时 |
| 关键字段缺失、日期/数值不合法或其他阻断性错误 | 输出预检查问题，不发布该期间的新矩阵 |

程序执行数量平衡检查，但**数量平衡不代表工时分配合理**。尤其在存在未映射业务时，留下的全天总工时可能覆盖矩阵之外的工作，求解结果应结合异常记录审查。

### 4.4 输出

| 文件 | 说明 |
|:---|:---|
| `output/<期间>_result.xlsx` | `矩阵_去除全零行`、`矩阵_保留全零行` 两表 |
| `output/<期间>_erro.xlsx` | 月度模式错误业务记录，注意后缀为 `_erro` |
| `output/<期间>_error.xlsx` | 年度模式错误业务记录 |
| `output/<期间>_precheck.xlsx` | 该期间存在预检查问题时生成 |
| `output/Resource_precheck.xlsx` | `Resource.xlsx` 结构或数据校验失败时生成 |

无相应错误时可能清理旧报告。某期间处理失败时，既存的同名矩阵不应视为本次运行结果。

## 5. 矩阵合并：`merge.py`

**输入：** `output/` 目录下符合 `YYYY_M_result.xlsx` 或 `YYYY_year_result.xlsx` 的文件。每个文件的**第一张工作表必须为 `矩阵_去除全零行`**，数据为非负有限数值，最后一列为工时。  
**输出：** `output/A_result.xlsx`，第一张工作表名称为 `汇总矩阵`，无表头、无日期列。

处理步骤：

1. 按文件名升序读取，文件内维持原始行序；通过校验且包含有效行的首份文件确定标准列数。
2. 跳过空行及全部数值为零的行；存在列数不一致、非数值、负数、公式、布尔值等错误时，**整份文件不参与汇总**。
3. 先删除**仅一个模块数量非零、且该数量严格小于 `SINGLE_MODULE_THRESHOLD = 10`** 的行。
4. 对其余行按**全部模块数量列及末列工时**进行精确正比例比较。成正比例的行仅保留最早出现的一行，不对保留值进行缩放或平均。

| 输出文件 | 生成条件与用途 |
|:---|:---|
| `A_result.xlsx` | 合并后的纯数值矩阵；供 `execute.py` 使用 |
| `A_logic.xlsx` | 存在单模块低数量删除行时，记录原文件和行号 |
| `delete.xlsx` | 存在相同或成比例重复方程时，两行一组记录保留与删除的来源 |
| `A_error.xlsx` | 存在文件格式、数值或列数校验错误时记录；无错误时不生成 |

**重要限制：** 列数相同并不证明不同期间的 `x1…xm` 含义一致。合并前须确认各期间使用同一套模块及相同列顺序；否则即使程序通过列数校验，合并矩阵仍可能不具有一致的业务含义。比例去重会减少重复约束，但也减少样本数；删除前后的报告应保留以备复核。

## 6. 参数求解：`execute.py`

### 6.1 输入及结果结构

- `data/Resource.xlsx` → `模块信息`：必须有 `备件模块`、`自变量`，并且必须且只能使用 `值` 或 `确定值` 中**一个**列作为固定工时输入。已填写的固定值必须为有限正数，空值表示待求解。
- `output/A_result.xlsx` → 第一张工作表 `汇总矩阵`：无表头纯数值矩阵，列数须等于模块数加一，数值须为非负有限数。
- 自变量须依次为 `x1…xm`；固定值及最终结果单位为**小时/件**，不是秒。

| 输出文件 | 内容 |
|:---|:---|
| `output/execute_result.xlsx` | `模块信息` 工作表：模块名、变量名、求解值（小时/件）、换算值（秒/件） |
| `output/execute_explain.xlsx` | 求解总览、样本拟合、模块诊断、异常记录、输入来源、配置参数、问题处理；部分模式另含过程记录 |

结果第三列为**小时/件**，第四列为第三列乘 `3600` 得到的**秒/件**。已给定固定值原则上保持不变；未通过验收的候选值不会作为正式数值写入结果表，其候选情况记录于解释报告。`*` 表示该未知模块没有业务样本。

### 6.2 可选模式

修改脚本顶部的 `MODE` 选择模式。**脚本不会根据求解结果自动切换模式。**

| 模式 | 方法 | 适用说明 |
|:---|:---|:---|
| `1.1` | 严格方程 | 在非负及严格正性约束下检查原始工时方程的可行性 |
| `1.2` | 非负最小二乘 | 以线性拟合残差平方和为目标；作为基准方法 |
| `1.3` | 相对误差加权 | 对总工时进行尺度加权，降低不同工时量级的影响 |
| `1.4` | Huber 稳健拟合 | 降低较大残差的影响，不自动删除异常样本 |
| `1.5` | L2 正则化最小二乘 | 引入参数惩罚，结果受正则强度和尺度影响 |
| `2.1` | 对数参数 MAP | 在对数单位工时空间使用正态先验的点估计；不是完整后验推断 |
| `2.2` | Bootstrap 集成 | 重采样并检查模块有效次数，报告条件经验分位区间 |
| `3.1` | 正权重线性神经网络 | 使用验证集选训练轮数，再全量重训，输出线性单位工时 |
| `3.2` | 非线性神经网络 | 仅用于总工时预测对照，**不输出固定的模块单位工时** |

### 6.3 核心参数与单位

| 参数 | 当前值 | 作用 |
|:---|:---|:---|
| `MODE` | `'1.2'`（原配置） | 求解方式；本轮选型见第7节 |
| `MIN_RESULT_SECONDS` | `0.5` | 未知模块结果验收下限，单位**秒/件** |
| `SEED` | `42` | 随机过程种子 |
| `CPU_THREADS` | `2` | 计算线程约束 |
| `MAX_ITER` | `3000` | 相关优化过程的迭代上限 |
| `ENABLE_VALIDATION` | `True` | 是否启用随机留出验证 |
| `VALIDATION_FRACTION` | `0.2` | 留出样本比例 |
| `MIN_VALIDATION_SAMPLES` | `20` | 启用留出验证的最少样本数 |
| `BOOTSTRAP_RUNS` | `50` | Bootstrap 重采样次数 |
| `REGULARIZATION` | `0.01` | 模式 `1.5` 的正则化系数 |
| `PRIOR_HOURS` | `0.01` | 模式 `2.1` 先验中位数，单位小时/件 |

验收条件为 `求解值（小时/件）×3600 < MIN_RESULT_SECONDS`。小于0.5秒判错，等于0.5秒不因该条件判错；该阈值仅筛选未知参数，不约束优化下限、不修改固定值。

其余模式参数（如 Huber 尺度、MAP 先验方差、Bootstrap 有效次数、神经网络训练配置及数值容差）以代码顶部配置为准，并在输出的 `配置参数` 表中记录实际取值。

### 6.4 验收、可识别性与解释限制

未知模块的正式输出需同时满足相应模式的求解状态、正值和阈值要求，以及基于矩阵的可识别性判断；Bootstrap 模式另检查模块有效抽样次数。无法独立识别的模块不能因优化器输出了一个数值就视为已确认。固定值不参与上述未知参数的下限筛选。

程序输出拟合误差、矩阵秩、模块诊断、来源文件哈希及参数记录。验证集采用**随机留出**而非按时间顺序留出；神经网络模式使用验证集选择训练轮数，因此对应指标不能当作独立测试集结果。正则化、先验和数值求解成功不等于实际作业工时的准确性，应结合独立测时、异常记录和业务口径开展复核。

**退出码：** `0` 当前任务完成；`1` 存在未通过验收的模块或求解未通过；`2` 输入、运行或输出失败。退出码 `1` 不必然表示程序发生异常，需查看解释报告。

### 7.3 方法评价

| 方法 | 专业适用性与本轮证据 | 本项目定位 |
|:---|:---|:---|
| 1.1 严格方程 | 当前非负等式不可行；日总人时含未建模活动时，严格等式假设通常过强 | 一致性检查 |
| 1.2 非负最小二乘 | 与“数量×固定单位工时”的模型直接对应，优化目标清晰；全量候选RMSE最低，但800个正候选值低于0.5秒 | 基准估计与问题诊断 |
| 1.3 相对误差加权 | 工时全部相同时权重一致，本轮与1.2结果相同 | 工时规模存在差异时再评估 |
| 1.4 Huber稳健拟合 | 对大残差降低权重；留出RMSE略有改善，MAE未改善，尚未体现明确优势 | 异常波动下的稳健对照 |
| 1.5 L2正则化 | 可缓解参数波动，但引入收缩偏差；当前参数下留出RMSE升至183.49小时 | 调参后复评 |
| 2.1 对数参数MAP | 保持正值并引入先验约束；固定工时模式中留出RMSE、MAE最低，但使用36秒/件先验中位数，需业务依据及敏感性检验 | 校准候选方案 |
| 2.2 Bootstrap | 用于评估重采样稳定性；50次抽样，通过265个，耗时较长；不能补足不可识别信息 | 稳定性诊断 |
| 3.1 正权重线性网络 | 可输出固定系数，选定994轮重训后覆盖范围最大；本质仍为线性加和，正值参数化与早停影响估计，不具备天然优于最小二乘的统计优势 | 覆盖性试算方案 |
| 3.2 非线性网络 | 仅预测总工时，无法直接解释为固定单位工时；3000轮后未通过稳定性判断 | 预测研究对照 |

### 7.4 综合选型意见

**建议采用“1.2基准估计、2.1校准候选、3.1覆盖性试算”的方法配置；现阶段不指定任何一组结果为正式标准工时。**

从方法与业务目标的一致性出发，1.2适合作为长期保留的基准：模型透明、目标明确，便于定位数据与线性假设的矛盾。其通过数较少应作为诊断信号，不能简单视为算法能力不足。

在需要兼顾正值估计和拟合效果时，2.1值得优先校准。其留出RMSE为129.38小时、MAE为102.29小时，略优于3.1的129.91小时和103.57小时；差异不足以确立统计优势，且36秒先验尚需实测支持。应在补充先验依据、检验参数敏感性后决定是否采用。

**若当前需要先形成较完整的模块工时试算表，可选3.1。** 其1098个模块通过检查，验收后覆盖2671行，明显高于2.1的206行，适合开展业务组合试算与测时安排。但较高覆盖率不能证明参数准确，早停验证也不等于独立测试或全局最优性证明。31个无法独立确定模块及192个无业务模块仍须单独处理。

### 7.5 有效性判断与改进重点

当前最关键的限制是**目标工时缺乏变化**。全部样本均为264小时，常数预测的留出RMSE即为0；因此3.2的低误差不能证明其识别了作业规律，其他模式的留出成绩也不足以验证单模块工时准确性。目标方差为0时，R²不适用。

下一阶段优先完成三项工作：

1. **统一数量与工时口径。** 核实264小时是否为固定出勤人时，排查期间重复、日期错配及未映射业务；区分有效包装作业与等待、搬运等活动。
2. **补充独立测时。** 优先覆盖高业务量、方法间差异较大及无法独立确定的模块，将经确认值以小时/件录入`Resource.xlsx`。
3. **开展独立验证。** 保留日期与来源，使用未参与调参的后续时段检验预测误差和参数稳定性；2.1增加先验敏感性检查，3.1增加随机种子与训练轮数稳定性检查。

验收标准应同时包含业务口径、参数可解释性、预测误差、稳定性与覆盖范围，不以通过模块数量作为单一依据。

## 8. 标准运行步骤

1. **准备映射（按需）：** 使用 `clean.py` 清洗主数据；使用 `model.py` 生成模块匹配建议，人工确认后维护 `data/Resource.xlsx`。两者均不自动更新 `Resource.xlsx`。
2. **确认基础信息：** 核对 Resource 的件号映射、模块顺序、`x1…xm` 编号；在 `模块信息` 中维护 `值` 或 `确定值` 单列以供求解器读取。矩阵生成阶段不要求逐一填写固定值。
3. **生成期间矩阵：** 按业务数据选择 `PROCESS_MODE` 和 `FIELD_MODE`，确认人均工时系数、业务文件命名及配套人员表后执行 `pre_execute.py`。
4. **审查数据质量：** 检查各期间预检查报告和错误明细，确认人员、业务范围和异常数量的处理口径。
5. **合并矩阵：** 确认各期间模块列含义一致后执行 `merge.py`，核对 `A_logic.xlsx`、`delete.xlsx` 和 `A_error.xlsx`（如有）。
6. **求解与评估：** 设置 `MODE`，执行 `execute.py`；以 `execute_explain.xlsx` 审核拟合误差、可识别性、验收结果及异常，再使用正式结果文件。

在项目目录执行：

主数据清洗（可选）：

```bash
python clean.py
```

模块辅助匹配（可选）：

```bash
python model.py
```

生成期间矩阵：

```bash
python pre_execute.py
```

合并矩阵：

```bash
python merge.py
```

执行求解：

```bash
python execute.py
```

每一步均应确认实际输出是本次运行生成的文件。运行前关闭 Excel/WPS 中已打开的同名目标文件，防止覆盖失败。含公式的输入工作簿应先完成公式计算并保存；不同脚本对公式读取方式不同，不能依赖未经计算的公式单元格。

## 9. 应用边界与版本管理

本轮初始结果保存在`result_initial/`。后续每轮计算建议同时归档输入版本、脚本配置、模块结果和解释报告，采用日期或批次区分；`output/`保留当前工作结果。

- **统计口径：** `pre_execute.py` 按人员数乘固定人均工时系数计算日总工时，该值不直接区分有效包装作业、等待及其他辅助活动。
- **业务覆盖：** 若存在未映射、缺失人员或日期异常的记录，须先评估有效矩阵是否仍能代表同范围的业务与工时。
- **模型前提：** 线性单位工时模型假设同一模块的作业件数可按固定系数叠加；实际工时还可能受包装差异、批量、设备和人员效率等影响。
- **可识别性：** 样本天数多于模块数并不自动保证可求解。长期同时出现或缺少独立变化的模块可能无法分别确定单位工时。
- **报告管理：** 程序可能覆盖同名结果或清理无异常时的旧报告；建议保留经审核的数据版本、模型配置及解释报告，以便复现和追溯。
